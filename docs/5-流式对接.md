## 5.1 目标与非目标

把发送路径从「等完整回答」切换为「逐段显示」：

1. 调用 `POST /api/chat/stream`，消费 SSE；
2. 收到 `delta` 就把文本追加到当前 AI 气泡；
3. 收到 `done` 视为正常结束；
4. 收到 `error` 或网络异常时给出可读错误；
5. 提供「停止」按钮，用户可中途取消。

**非目标**：Markdown 渲染、历史消息接口、鉴权、工具调用、RAG。同步接口 `POST /api/chat` 保留，可作为降级方案，但本次主链路走流式。

## 5.2 接口契约

请求体与 `/api/chat` 完全相同：

```json
{
  "message": "用三句话介绍你自己",
  "conversationId": "0f8fad5b-d9cb-469f-a165-70867728950e"
}
```

请求头：`Content-Type: application/json`，建议带 `Accept: text/event-stream`。

响应：`text/event-stream`，事件帧如下（空行分隔）：

```
event:delta
data:{"content":"我是"}

event:delta
data:{"content":" Polaris"}

event:done
data:{"conversationId":"0f8fad5b-d9cb-469f-a165-70867728950e"}
```

| event | data | 含义 |
|---|---|---|
| `delta` | `{"content":"片段"}` | 追加一段文本 |
| `done` | `{"conversationId":"..."}` | 正常结束，之后不会再有事件 |
| `error` | `{"message":"模型调用失败：..."}` | 上游失败；流随即关闭 |

错误语义：

| 场景 | HTTP | 前端怎么处理 |
|---|---|---|
| `message` 为空 / `conversationId` 为空或超长 | 400 | 流开始前返回 JSON 错误体；按普通请求失败处理 |
| 模型 key 错误、provider 异常 | 200 + `event:error` | 展示 `error.message`，保留已显示的部分回答 |
| 后端未启动 / 网络中断 | fetch 抛异常 | 展示「无法连接后端服务」 |
| 用户点击停止 | 连接被 abort | 不报错，静默结束 |

> 流开始后 HTTP 状态固定 200，**不能**用 `response.ok` 判断模型是否成功；必须看 `event:error`。

动手前先绕过前端，用 curl 确认后端行为：

```bash
printf '{"message":"用三句话介绍你自己","conversationId":"11111111-1111-1111-1111-111111111111"}' > /tmp/polaris-stream.json
curl -N -X POST http://localhost:8103/api/chat/stream \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-stream.json
```

`-N` 关闭 curl 缓冲；中文请求体写 UTF-8 文件，避免 Windows 终端 GBK 编码问题。

## 5.3 技术选型：fetch + ReadableStream

| 方案 | 能否用 | 原因 |
|---|---|---|
| `EventSource` | ❌ | 只支持 GET，无法发送 JSON 请求体 |
| Axios | ❌ | 浏览器适配器会缓冲完整响应，拿不到增量；`responseType: 'stream'` 只在 Node 可用 |
| `fetch` + `response.body.getReader()` | ✅ | 原生支持 POST + 流式读取，无需新依赖 |
| 第三方 SSE 解析库 | 不必要 | 本项目事件格式固定，`\n\n` 分帧 + 简单字段解析足够，**不要新增 npm 依赖** |

Vite 开发代理（5174 → 8103）对 `fetch` 同样生效，继续使用相对路径 `/api/chat/stream`，不要写死后端地址。

### 5.4.2 新建 `src/api/chatStream.ts`

建议 API：回调式，返回 Promise，结束时 resolve。

```ts
import { ApiError } from '@/api/client'
import type {
  ChatRequest,
  ChatStreamDelta,
  ChatStreamDone,
  ChatStreamError,
} from '@/types/api'

export interface ChatStreamHandlers {
  onDelta: (content: string) => void
  onDone: (conversationId: string) => void
  onError: (message: string) => void
}

export async function postChatStream(
  payload: ChatRequest,
  handlers: ChatStreamHandlers,
  signal?: AbortSignal,
): Promise<void> {
  let response: Response
  try {
    response = await fetch('/api/chat/stream', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        Accept: 'text/event-stream',
      },
      body: JSON.stringify(payload),
      signal,
    })
  } catch (error) {
    if (signal?.aborted) throw error
    throw new ApiError('无法连接后端服务，请确认 http://localhost:8103 已启动')
  }

  if (!response.ok) {
    throw new ApiError(`请求失败（HTTP ${response.status}）`, response.status)
  }
  if (!response.body) {
    throw new ApiError('当前浏览器不支持流式响应')
  }

  const reader = response.body.getReader()
  const decoder = new TextDecoder('utf-8')
  let buffer = ''
  let sawDone = false
  let sawError = false

  const consumeFrames = () => {
    buffer = buffer.replace(/\r\n/g, '\n')
    let boundary = buffer.indexOf('\n\n')
    while (boundary >= 0) {
      const frame = buffer.slice(0, boundary)
      buffer = buffer.slice(boundary + 2)
      const result = dispatchFrame(frame, handlers)
      if (result === 'done') sawDone = true
      if (result === 'error') sawError = true
      boundary = buffer.indexOf('\n\n')
    }
  }

  try {
    while (true) {
      const { value, done } = await reader.read()
      if (done) break
      buffer += decoder.decode(value, { stream: true })
      consumeFrames()
    }
    buffer += decoder.decode()
    consumeFrames()
  } catch (error) {
    if (signal?.aborted) throw error
    if (error instanceof ApiError) throw error
    throw new ApiError('连接中断，回答可能不完整')
  }

  // error 事件之后连接也会关闭，不能误判成「中断」
  if (!sawDone && !sawError) {
    throw new ApiError('连接中断，回答可能不完整')
  }
}

function dispatchFrame(
  frame: string,
  handlers: ChatStreamHandlers,
): 'done' | 'error' | null {
  let event = 'message'
  const dataLines: string[] = []

  for (const line of frame.split('\n')) {
    if (!line || line.startsWith(':')) continue
    const colon = line.indexOf(':')
    const field = colon >= 0 ? line.slice(0, colon) : line
    let value = colon >= 0 ? line.slice(colon + 1) : ''
    if (value.startsWith(' ')) value = value.slice(1)
    if (field === 'event') event = value
    else if (field === 'data') dataLines.push(value)
  }
  if (dataLines.length === 0) return null

  const data = dataLines.join('\n')
  if (event === 'delta') {
    handlers.onDelta((JSON.parse(data) as ChatStreamDelta).content)
  } else if (event === 'done') {
    handlers.onDone((JSON.parse(data) as ChatStreamDone).conversationId)
    return 'done'
  } else if (event === 'error') {
    handlers.onError((JSON.parse(data) as ChatStreamError).message)
    return 'error'
  }
  return null
}
```

要点：

- `TextDecoder.decode(value, { stream: true })` 必须带 `stream: true`，否则一个中文字符被切在两个 chunk 之间时会乱码。
- 事件帧可能跨多次 `read()`、一次 `read()` 也可能包含多帧，所以要用缓冲区 + 循环找 `\n\n`。
- `\r\n` 统一成 `\n`，兼容不同容器 / 代理。
- 判断「正常结束」看有没有收到 `done`，不要只看连接关闭。

### 5.4.3 `src/stores/chatStore.ts`

在 M2 store 基础上改：

- 删除对 `postChat` 的调用，改用 `postChatStream`。
- `sending` 表示「流进行中」，仍然作为互斥锁。
- 发送时**立刻插入一条空的 assistant 消息**作为占位，`onDelta` 时按 id 追加；不要每个 token 新建消息。
- 用一个模块级 `AbortController` 支持停止；`stop()` 调用 `abort()`。
- `newConversation()` 先 abort 正在进行的流，再换会话。

核心结构：

```ts
let activeAbort: AbortController | null = null

send: async (content) => {
  const text = content.trim()
  if (!text || get().sending) return

  const conversationId = get().conversationId
  const assistant = createMessage('assistant', '')

  set((state) => ({
    messages: [...state.messages, createMessage('user', text), assistant],
    sending: true,
    error: null,
  }))

  const abort = new AbortController()
  activeAbort = abort

  try {
    await postChatStream(
      { message: text, conversationId },
      {
        onDelta: (chunk) => {
          set((state) => ({
            messages: state.messages.map((message) =>
              message.id === assistant.id
                ? { ...message, content: message.content + chunk }
                : message,
            ),
          }))
        },
        onDone: () => {},
        onError: (message) => set({ error: message }),
      },
      abort.signal,
    )
  } catch (error) {
    if (!abort.signal.aborted) {
      set({ error: toErrorMessage(error) })
    }
  } finally {
    set((state) => ({
      sending: false,
      // 失败 / 立即停止时不要留下空气泡
      messages: state.messages.filter(
        (message) => message.id !== assistant.id || message.content !== '',
      ),
    }))
    if (activeAbort === abort) activeAbort = null
  }
},

stop: () => {
  activeAbort?.abort()
  activeAbort = null
},
```

注意事项：

- `AbortError` 不要当失败展示；用 `signal.aborted` 区分。
- 收到 `event:error` 时保留已经显示的文本，同时展示错误 Alert（部分回答是有价值的）。
- 若 M2 已做 localStorage 持久化，**不要每个 delta 都写一次**；在 `finally` 或 `done` 时写，避免高频序列化。

## 5.5 边界与坑

### 现象 → 原因 → 规避

1. **中文出现乱码或半个字**
   - 原因：多字节字符被 TCP / fetch 分片切开。
   - 规避：`TextDecoder` 必须用 `{ stream: true }`，并在流结束后再 `decode()` 一次。

2. **一直接收不到事件**
   - 原因：按「每次 read 就是一条完整事件」解析，但帧可能被拆开；或者漏了跨帧缓冲。
   - 规避：维护字符串缓冲区，按 `\n\n` 切帧；一次 read 可能产出 0 到多个事件。

3. **进度不是逐段出现，而是一次性全出**
   - 原因：用了 Axios，或中间层开了压缩 / 缓冲。
   - 规避：浏览器端用 fetch 原生流；先用 `curl -N` 确认后端逐段到达。若日后加 nginx，需要关闭该路由的 `proxy_buffering`。

4. **模型出错但前端没有报错**
   - 原因：只看 `response.ok`。流开始后 HTTP 状态是 200。
   - 规避：监听 `event:error`；同时处理「连接结束但没有 `done`」的情况。

5. **点击停止后仍不断追加**
   - 原因：abort 了 fetch，但 `onDelta` 回调仍然在闭包里改状态。
   - 规避：abort 后以 `signal.aborted` 为准，忽略后续回调；`finally` 里统一收尾。

6. **刷新页面后出现「只有提问没有回答」**
   - 原因：后端只在流正常完成时保存 ASSISTANT 消息；断开 / 停止时只保存了 USER。
   - 规避：前端持久化以本地展示为准；不要在刷新后自行伪造回答。文档已知限制见后端 [12-流式输出](../12-流式输出.md) ⑤。

### 没做什么

- 没有自动重连：流断开后由用户重新发送，避免重复计费。
- 没有把「已回答部分」提交回后端保存。
- 没有做 token / 首字延迟统计。
