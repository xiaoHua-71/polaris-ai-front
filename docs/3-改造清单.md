# 3 · 改造清单

按文件逐项修改。

## 3.1 `src/types/api.ts`

```ts
export interface ChatRequest {
  message: string
  conversationId: string
}
```

`ChatResponse` 不变。

## 3.2 `src/api/chat.ts`

`postChat(payload: ChatRequest)` 签名不变；确认调用方传入了 `conversationId`。

## 3.3 `src/stores/chatStore.ts`

要求：

- 新增状态 `conversationId: string`，初始化时调用 `loadOrCreateConversationId()`。
- `send(content)` 调用 `postChat({ message: text, conversationId: get().conversationId })`。
- 新增 `newConversation()`：生成新 ID、清空 `messages`、清空 `error`。
- 删除或改名现有 `clear`：**「清空」的行为改为「新会话」**，避免出现「界面清了但模型还记得」的割裂。
- 保留 `sending` 互斥：请求进行中不允许再次发送。
- 按 [2-会话ID规则](2-会话ID规则.md) §2.3 持久化消息记录。

## 3.4 `src/pages/ChatPage.tsx`

- 把「清空」按钮改为「新会话」，仅在 `messages.length > 0` 或已有 `conversationId` 时显示；点击调用 `newConversation()`。
- 副标题从「当前为单轮、非流式」改为「多轮记忆（非流式）」。
- 发送前仍然 `trim()`；空白输入不发请求。
- 可选：在页脚显示 `conversationId` 前 8 位，方便联调；不是验收项。
- 现有加载态、错误 Alert、自动滚动保持。

## 3.5 `README.md`

更新「当前接口契约」和「当前范围」：

- `POST /api/chat` 请求体变为 `{ message, conversationId }`；
- 多轮会话从 ⬜ 改为 ✅；
- 说明会话 ID 存在 `localStorage`，以及「新会话」的行为。

## 3.6 不要改

- `vite.config.ts` 的代理和端口；
- `src/api/client.ts` 的错误包装（除非有 bug）；
- Ant Design 主题和布局；
- 不要修改后端仓库中的任何文件；
- 不要新增 npm 依赖。
