# 4 · 验收清单

## 4.1 前置

1. 后端首次启动前，先在后端仓库执行建库建表脚本（可重复执行）：
   ```bash
   mysql -u root -p < sql/schema.sql
   ```
2. 后端已启动（8103），且设置了 `MYSQL_PASSWORD`；前端 `npm run dev`（5174）。

## 4.2 验收项

| # | 操作 | 预期 |
|---|---|---|
| 1 | 发送「我叫 Alice，请记住」 | 200，正常回答 |
| 2 | 同一页面发送「我叫什么？」 | 回答包含「Alice」 |
| 3 | 刷新页面后再问「我叫什么？」 | 仍回答包含「Alice」（同一 conversationId + 后端 MySQL） |
| 4 | 点击「新会话」，再问「我叫什么？」 | 不再回答 Alice（新 ID，历史为空） |
| 5 | 重启后端，刷新页面，再问一次 | 仍记得 Alice（MySQL 持久化） |
| 6 | 用无痕窗口打开前端 | 生成新 ID，不与原窗口串话 |
| 7 | 后端停止后发送消息 | 显示「无法连接后端服务」类错误，不是白屏 |
| 8 | 只输入空格后发送 | 不发送请求 |
| 9 | `npm run build` / `npm run lint` | 通过 |

## 4.3 数据库抽查（可选）

```sql
SELECT conversation_id, message_type, content
FROM chat_message
WHERE conversation_id = '<前端 localStorage 里的 ID>'
ORDER BY id;
```

应能看到 USER / ASSISTANT 交替的记录，且条数不超过 20。

## 4.4 边界与注意事项

- **无历史查询接口**：前端无法从后端拉取历史；刷新后的历史展示只能依赖前端本地持久化。
- **无鉴权**：conversationId 即凭据，前端不要把它展示在公开页面或日志里（调试展示前 8 位可以）。
- **非流式**：M2 阶段一次请求等完整回答，现有 loading 动画继续使用；M3 切流式后以 [5-流式对接](5-流式对接.md) 为准。
- **单会话窗口 20 条消息**：超出后后端自动裁剪，前端无需感知。
- **并发**：前端已有 `sending` 互斥；不要绕过它并发提交同一会话。
- **契约变更只认本文件组**：如果实际响应与文档不符，停止实现并向后端反馈，不要自行兼容猜测。

## 4.5 交付要求

- 提交前跑 `npm run lint` 和 `npm run build`。
- 在 README 记录本次改造涉及的文件和验收结果。
- 不要修改后端仓库中的任何文件。
